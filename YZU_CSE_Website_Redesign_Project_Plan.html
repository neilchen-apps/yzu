01 / 本次Project的主要目的

透過資訊系網站重設計，學會說明「為什麼這樣設計」，並用HTML、CSS與適量互動把想法呈現出來。

本專題以內容作為導覽依據：系所介紹、課程、師資、研究、公告與資源自然地連成網站。首頁不要求依身分建立不同入口。所有訪客都可沿著內容主題探索。

觀察問題 → 提出理念 → 比較方案 → 實作呈現 → 測試修正

每個設計決策都留下「目的、做法、取捨、驗證」四項說明。頁面與互動是用來展示這些決策的成果。

02 / 八個設計理念：把理由說清楚

設計沒有單一漂亮答案。每個方案都有適用情境與代價；學生要能指出自己的選擇如何幫助理解、查找或操作。

PRINCIPLE 01 / 資訊組織

讓內容可理解、可查找

把系所介紹、課程、師資、研究、公告、活動與資源依內容分組。同一項資料維持一個明確位置，再從其他區域連過去。導覽名稱應描述目的地，不使用讀者猜不出的詞。

系網例子

例如把「更多」「其他」改成「課程文件」「研究方向」。公告摘要包含日期、類別與有效的全文連結；沒有內容的裝飾區塊可以刪除。

設計前先問：主要內容是否在自然的位置？一個入口名稱能否預測點進去看到什麼？

如何驗證：請另一位同學找課程文件、某位教師、最近活動，記錄卡住位置。

PRINCIPLE 02 / 視覺層級

讓重要內容先被看見

層級可由位置、大小、字重、對比與留白共同建立。主標題不是越大越好；它必須和次標題、正文、按鈕形成可辨識的階層。全頁每個區塊都用最鮮明的樣式，會讓讀者不知道從哪裡開始。

系網例子

首頁先呈現系名與一句定位，再提供內容入口、公告與研究摘要。重要公告可用醒目標記，但正文仍使用穩定字級。

設計前先問：這頁第一眼應該看到哪三件事？次要內容為什麼放在後面？

如何驗證：把頁面縮成截圖，請同學說出先看到的三項；比較和你的預期是否一致。

PRINCIPLE 03 / 配色系統

讓顏色有職責

先定義底色、表面色、正文色、次要文字色、主色、重點色與狀態色，再指定到元件。品牌色、連結色與警告色不一定相同。顏色可以塑造氣氛，但不能單獨表示內容或狀態。

系網例子

以藍色呈現連結、暖色標記重要日期；標記同時寫「重要」或「截止日」。深色背景不等於所有文字都要亮青色。

設計前先問：哪個色是正文？哪個表示可點擊？亮色按鈕上的字色如何選？

如何驗證：計算實際前景／背景色的對比；檢查一般文字、按鈕、連結及焦點。

PRINCIPLE 04 / 字體與閱讀

讓長內容舒服可讀

正文以清楚的系統字體為起點，標題可探索襯線或較強的字重。用固定的字級階層、行高與段落間距維持節奏。中文正文可先以16–18px、行高約1.7–1.9試作，再依實際字體與裝置調整。這些是教學起點，不是通用標準。

系網例子

公告列表用一致的日期、標題與摘要；長簡介分段、加小標，不把一整頁擠成巨大文字牆。

設計前先問：文字縮放後還可讀嗎？一行是否太長？是否為裝飾用了過細的正文？

如何驗證：測試200%文字縮放、手機長標題與較長中文段落。

PRINCIPLE 05 / 排版與節奏

讓版面對應內容的關係

單欄適合連續閱讀，左右分區能並列重要資訊，卡片適合重複類型，編輯式布局可凸顯故事與成果。對齊、間距和最大寬度比任意放大圖片更能建立秩序。以內容關係選版型，再做裝飾。

系網例子

同一組課程可做卡片網格，也可按學期做清單；前者便於概覽，後者便於理解順序。卡片過多時要重新分組，而不是無限加陰影。

設計前先問：這些內容是並列、先後還是主次關係？選Grid或Flex的原因是什麼？

如何驗證：保留同一內容做至少兩種布局，比較掃讀、閱讀順序與手機變化。

PRINCIPLE 06 / 互動與回饋

讓每次操作有清楚結果

每個互動都要回答：如何開始、可操作的提示、操作後的狀態、如何返回、鍵盤是否可用。互動可用來揭露細節、分類、定位或比較；動畫只是其中一種呈現。

系網例子

FAQ展開答案；分類切換後顯示對應內容；卡片連結在hover與鍵盤焦點時都有提示。必要資訊在沒有滑鼠hover時仍可看到。

設計前先問：這個互動減少了什麼困惑？使用者知道剛才發生了什麼嗎？

如何驗證：用滑鼠、Tab／Enter與手機實測；檢查開啟、關閉、空內容與焦點狀態。

PRINCIPLE 07 / 一致性與元件

讓整個網站像同一套系統

將常用按鈕、卡片、導覽、表格和狀態標記定義為共用元件。用CSS變數管理顏色、字級、間距、圓角與陰影。相同功能應維持相同樣式，不同功能才表達不同層級。

系網例子

「查看課程」和「查看研究」若都是一般入口，就採相同按鈕規則；主要行動才使用更強的視覺權重。

設計前先問：只改一個主色變數，哪些區域應一起變？相同卡片是否使用同一class？

如何驗證：跨頁檢查導覽、連結、按鈕和表格；更換主題後仍保持元件關係。

PRINCIPLE 08 / 響應式與包容性

讓不同裝置與操作方式都能理解

不要只把桌面縮小。窄螢幕要重排欄位、容許導覽換行、處理長字與表格；圖片不推破容器。使用語意區域、合理標題層級、圖片alt與清楚的鍵盤焦點，提供減少動態效果的版本。

系網例子

雙欄公告與研究在手機改為單欄；寬課程表在自己的容器水平捲動，整個頁面保持可讀。

設計前先問：手機版保留了最重要的內容嗎？沒有顏色、動畫或hover時還能理解嗎？

如何驗證：至少測試360／768／1280px、Tab操作、文字縮放與減少動態效果。

把設計理念寫成可討論的句子

太模糊的說法可驗證的設計說明
「藍色很科技」「以深藍作正文與導覽，亮色只標示連結；讓長公告保持可讀，並把可操作元素區別出來。」
「卡片很潮」「研究方向是四組並列資訊，採一致卡片便於掃讀；手機改單欄，避免中文標題過窄。」
「加入動畫比較漂亮」「卡片hover和鍵盤焦點提供可點擊提示；位移限制在小範圍，減少動態設定下取消位移。」
「手機版縮小即可」「雙欄內容改為單欄，保留相同資訊；表格在局部容器捲動，避免整頁水平溢出。」

合理標題與語意區域能協助導覽與定位，相關原則可參考W3C頁面結構教材。對比與互動實作來源列於文末。

03 / 把風格、配色、排版分開探索

這三個面向可以組合。極簡風可以用暖色；深色頁面也可以採編輯式布局。保留同一內容比較，才能看出每個面向帶來的改變。

面向控制什麼可探索的方向
風格字體、字重、框線、圓角、陰影、圖片處理極簡清晰／編輯敘事／鮮明幾何／科技介面／溫暖人文
配色背景、表面、正文、次要文字、主色、重點色藍白清晰／深色青紫／米白森林綠／低彩度灰／鮮明撞色
排版欄位、對齊、內容先後、卡片大小、空間分配置中概覽／左右分區／雜誌布局／公告優先／長頁敘事
互動展開、分類、定位、滑動、回饋與狀態FAQ／分類切換／頁內導覽／水平圖文探索／hover與focus

三種比較方式

  1. 控制變因：固定布局與風格，只換色盤；說明氣氛和可讀性怎麼變。
  2. 單項試驗：固定文字、圖片與色盤，比較卡片網格與編輯式布局。
  3. 完整提案：整合風格、配色、布局與互動，提出A／B／C三個方案，說明各自的優點、代價與最後選擇。
避免：三個方案同時改文案、刪內容、換圖片又換布局，最後只憑印象說哪個比較好。方案比較先保持內容一致；必要內容改寫在設計紀錄中說明。

05 / 同一份資訊可以怎麼排？

布局設計理念適合內容需要注意
置中概覽先建立整體印象，再逐區探索精簡定位、特色、研究與成果摘要不能每個區塊都大面積置中；長正文仍應方便閱讀
左右分區同時呈現兩組相關但不同的內容主要介紹＋特色；研究摘要＋消息手機先後順序要明確，不能單純縮成窄雙欄
卡片網格把並列項目做成可比較的單位研究方向、教師、課程、作品內容長短不一時注意對齊；卡片太多須再分類
公告優先快速掃讀日期、標題與類別頻繁更新的公告與活動既保留摘要，也避免單頁塞滿多年資訊
編輯／雜誌式透過大小差異引導主次與故事節奏重點研究、訪談、作品與成果跨欄布局在手機要有穩定閱讀順序
長頁敘事讓訪客沿一條內容線逐步理解系所理念、學習路徑、專題歷程要有頁內導覽與回到頂端，避免資訊只能一直滑

06 / 配色不只是選三個喜歡的色碼

先定義角色，再選顏色。下面三套可作起點；學生可以提出自己的色盤。風格與布局沒有被這些色盤綁定。

色盤底色／正文主色／按鈕字視覺氣氛與注意事項
藍白清晰#F5F7FA／#172B4D#005FCC／#FFFFFF高明度、穩定；重點色節制使用
深色青紫#0B1220／#F1F5F9#67E8F9／#081321深色層次；主色很亮，按鈕須改深色字
米白森林綠#FAF7F0／#2D241F#285B48／#FFFFFF溫暖、文字與圖片節奏；可搭陶土重點色

同是白底，正文可讀性也可能不同

這段是低對比示例，供比較用。

#9AA8B7／#FFFFFF；不作正式正文建議。

這段使用較明確的正文色。

#172B4D／#FFFFFF。

依WCAG 2.2的一般文字最低對比要求，通常至少4.5:1；符合大型文字條件者至少3:1。大型文字約為24 CSS px一般字重，或18.7 CSS px粗體；不要只把任意標題算成大型文字。本課可先以所有正文和一般按鈕文字達4.5:1為目標，不等於整站已符合完整無障礙規範。

來源：W3C SC1.4.3說明。色差、標記、底線與文字要一起運用；「紅色表示重要」仍須加上「重要」等文字。

用CSS變數管理同一套色彩角色

:root {
  --bg: #F5F7FA;
  --surface: #FFFFFF;
  --text: #172B4D;
  --muted: #44546F;
  --accent: #005FCC;
  --on-accent: #FFFFFF;
  --space: 24px;
  --radius: 14px;
}
body { background: var(--bg); color: var(--text); }
.card { background: var(--surface); padding: var(--space); }
.button { background: var(--accent); color: var(--on-accent); }
/* 換成亮青色accent時，同時檢查on-accent字色。 */

07 / 各式互動：先說目的，再選技術

互動可以協助探索內容，也可以提供操作回饋。每個互動都寫一張小規格：目的 → 觸發 → 状態 → 回饋 → 返回／關閉 → 鍵盤與手機測試。

呈現可以解決什麼技術注意事項
FAQ展開先看到問題，再選擇閱讀細節原生details／summary；HTML＋CSS標題可理解；開閉狀態可辨識
卡片hover／focus提示這是可點擊入口CSS :hover／:focus-visible必需內容不能藏在hover，手機沒有同樣的懸停
頁內導覽定位長頁與返回目錄a錨點＋CSS有效id；減少動態設定下不強制平滑捲動
分類切換比較不同類別的一小組內容原生radio＋CSS；正式資料篩選可選JS使用radio就保留radio語意，不假裝完整ARIA tabs
水平圖文探索在有限空間保留卡片序列overflow-x＋scroll snap標明可水平捲動；提供文字內容，不自動播放
月曆與活動清單把日期與活動連起來靜態table＋錨點；換月可選JS手機提供清單；日期正確；不只用顏色標記
即時主題／布局切換比較設計方案CSS設定＋少量JS目前狀態清楚；有預設可讀版本
搜尋／篩選縮小公告、教師或課程結果可選JS要做無結果、重設與結果數，不只放裝飾輸入框
內容視窗／影片暫時聚焦詳細內容可選JS或適用的原生元件關閉方式、焦點、鍵盤與背景操作都須設計

08 / 專題成果：設計提案與網站一起提交

系所簡介、課程、師資、研究、公告、活動、資源與聯絡是本次可用的八類內容。它們可以合理合併成頁面；重要的是分類、完整性與可理解性。

建議最低作品範圍

  • 一個主站：首頁＋至少四個內容頁，合理涵蓋上述八類內容。可做更多頁，但頁數不是主要加分依據。
  • A／B／C三個首頁方案：保留相同核心內容，展示不同風格、配色與排版；主站選一方案延伸。
  • design.html設計說明：觀察問題、理念、色彩角色、版型、字體、元件規則、互動規格、比較與測試。
  • 至少三項互動：逐項說明目的、狀態與操作方式；不要把装飾動畫直接算成三個互動。
  • 證據：三個方案各有360px與1280px截圖共六張；主站另測768px，附兩位同學的查找與互動測試。

一筆完整設計紀錄示例

目的：讓課程與研究的並列關係容易掃讀。

做法：用四張相同的卡片，固定標題、摘要與入口；深藍正文，藍色連結，24px間距。

取捨：卡片方便概覽，但長摘要會讓整組太高，因此摘要先精簡為兩句，細節連到內頁。

驗證：檢查手機單欄與1280px網格；請同學找指定內容，記錄是否認出連結。這段描述是紀錄格式示例，不是已完成的測試結果。

分階段完成

  1. 觀察系網內容，列出三個具體設計問題與來源。
  2. 先畫灰階草圖，只討論區塊、內容順序與排版。
  3. 用HTML把內容與有效連結完成，再做共用CSS。
  4. 固定內容，建立A／B／C方案，附每項設計理由。
  5. 加入互動，檢查全部狀態與鍵盤操作。
  6. 完成手機版、比較、測試與修正，再練習Demo。

進度可沿用第5週開發、第9週Demo的課程草案；正式日期、分組與成績權重依教師公告。全班若使用同一份內容快照，方案比較更容易聚焦設計。

「我喜歡」「看起來科技」可以是起點，但需要接著說出具體做法與可驗證的效果。複雜動畫、更多頁數與額外JS不直接多得分。好的作品能說明自己的选择，也知道仍有什麼限制。

Demo建議8分鐘

  1. 2分鐘：三個觀察問題與設計理念。
  2. 2分鐘：A／B／C風格、色盤、排版比較與最終選擇。
  3. 2分鐘：三項互動，展示鍵盤或手機狀態。
  4. 2分鐘：一個測試發現、修正前後、現場改CSS。

上台重點是解釋決策與證據。各組可以採不同風格與排版，只要內容、互動與可讀性有清楚理由。
